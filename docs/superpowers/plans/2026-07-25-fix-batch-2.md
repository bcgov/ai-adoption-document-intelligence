# Fix Batch 2 — Make the Screen Tell the Truth

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A port bound to a variable that no longer has a source must say so — on the node badge, in the validation drawer, and in the settings row. Today all three report it healthy.

**Architecture:** One shared source-lookup helper in `@ai-di/graph-workflow`, then three consumers switched onto it. The three findings are one root cause: nothing anywhere answers "does this variable actually have a source?" in a way all surfaces share.

**Tech Stack:** TypeScript, Jest (`packages/graph-workflow`), Vitest (`apps/frontend`).

**Source:** G-002, G-005, G-013 in [GAP_REGISTER.md](../../../feature-docs/20260724-workflow-builder-spec-completion/GAP_REGISTER.md) · plain-language context in [FIX_SET_EXPLAINED.md](../../../feature-docs/20260724-workflow-builder-spec-completion/FIX_SET_EXPLAINED.md)

## The one rule this batch establishes

> **A port binding is satisfied only if its `ctxKey` has a real source: some node writes that key as an output, or the key is declared in `config.ctx`. Otherwise the port has a problem, and every surface must say so.**

Everything below follows from that sentence. Today:

- **G-005** — `resolveInputPort` returns `{ status: "locked" }` for a pinned port the moment a binding row exists, without checking the key has a source or that its kind fits (`resolve-input-port.ts:59-62`).
- **G-002** — the badge pipeline *deliberately* skips manually-bound ports (`auto-wire-validation.ts:34`, `if (manuallyBoundPorts.has(problem.port)) continue;`) because "a ctx-bound port HAS a source" — true until its producer is deleted. Independently, the validator's type-compatibility walk skips any key with zero producers (`validator.ts:1500`, `if (producers.length === 0 || consumers.length === 0) continue;`). A hand-bound port whose producer was deleted falls through **both**.
- **G-013** — `map.collection` has no descriptor, no kind, no row and no resolution state, and its auto-fill is one-shot (`resolver.ts:29`, `if (mapNode.collectionCtxKey) continue;`) so it never re-resolves once the producer is gone.

**A declared `config.ctx` entry is a legitimate source.** Workflow inputs have no producing node and must stay healthy. Do not treat "no node produces it" as sufficient for a problem.

## Notes for the implementer

**This batch makes validation stricter, so existing content may start failing.** That is the point, but each new failure needs a judgement: real latent bug (fix the content) or false positive (fix the rule). Never silence a failure by loosening the rule without saying so.

**Two tests are known to encode the defect:** `resolve-input-port.test.ts:186` and the `manuallyBoundPorts` suppression tests. Expect to edit them. A green test you must change is the signal you found a real gap.

**Declared `config.ctx` entries are legitimate sources.** The most likely way to get this batch wrong is to flag every workflow input as dangling. If your change makes shipped templates fail *en masse*, that is almost certainly what happened.

**Do not fix anything outside G-002, G-005, G-013.** In particular: control-flow output ports (G-007), errorPolicy (G-001) and preview coverage (G-011) are later batches with their own designs.

**If the shared helper turns out not to unify all three cases, stop and report.** The batch is built on the claim that these are one root cause; if that is wrong, the plan needs rethinking rather than three separate patches.
