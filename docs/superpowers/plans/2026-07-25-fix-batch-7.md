## Task 1 — G-012: "didn't run" currently means four different things

`notRunMessage` (`apps/frontend/src/features/workflow-builder/preview/PreviewWidget.tsx:~58`) returns **one sentence** for `pending`, `running`, `cancelled` and absent. Its own comment concedes the conflation ("the branch was not taken or the run never reached this node"). Those are different situations with different user actions: *wait*, *look elsewhere*, *the run is over*.

The concept has **no enum, no named literal and no type** — it is a computed copy string under a shared `data-state="not-run"`. `WirePeekPopover` calls the same derived state `no-run`, types `state` as bare `string`, and emits it from two further causes.

**And the honest copy is gated behind `isReplay`** — during a live Try the branch is a bare `return null`, so the most informative moment shows nothing.

**Files:**
- Modify: `PreviewWidget.tsx`, `WirePeekPopover.tsx`, and wherever the shared state belongs
- Test: their specs

- [ ] **Step 1: Give the concept a type**

Create a named union for why there is no output — e.g. `didn't run yet` / `running now` / `failed` / `branch not taken` / `cancelled` / `evicted`. Put it somewhere both `PreviewWidget` and `WirePeekPopover` import, so one derived state stops having two names and six loose literals.

**The exhaustiveness is the point.** Use a `never` check so adding a run status without deciding its copy fails compilation. This is the regression floor for the class — the original bug was an unhandled branch falling into a catch-all.

- [ ] **Step 2: Write failing tests**

```ts
it.each([...])("renders distinct copy for %s", () => {});
it("distinguishes a branch that was not taken from a node that never started", () => {});
it("shows a state during a live run, not a blank", () => {});
it("still shows the eviction message with its Re-run action for a genuine TTL eviction", () => {});
```

That last one is the regression guard: eviction is a *different* cause with a *different* remedy, and it must not get folded into "didn't run".

- [ ] **Step 3: Run, watch fail. Step 4: Implement. Step 5: Green.**

- [ ] **Step 6: Commit**

```bash
git add apps/frontend/src/features/workflow-builder/preview apps/frontend/src/features/workflow-builder/canvas
git commit -m "fix(workflow-builder): every reason a step has no output gets its own honest state (G-012)"
```

## Task 2 — G-011: the preview shows one output, for a third of the kinds

Four defects in one surface:

1. **First output only.** `WorkflowEditorCanvas.tsx:1277` projects `primaryOutputCtxKey: node.outputs?.[0]?.ctxKey`. A node with several outputs — the whole reason port rows exist — has every output after the first invisible, with no way to switch.
2. **Kind coverage.** `render-kind-value.tsx` dispatches on family root and handles only `Document`, `OcrResult`, `Classification`, plus `Segment` arrays. Everything else falls to `default: return null`.
3. **A blank card doesn't say why.** `null` renders as nothing, indistinguishable from a bug.
4. The wire-peek workaround only exists where a data wire was drawn, so an unconsumed second output is unobservable.

**Files:**
- Modify: `WorkflowEditorCanvas.tsx` (the projection), `PreviewWidget.tsx`, `render-kind-value.tsx`
- Test: their specs

- [ ] **Step 1: Establish the real kind list**

Enumerate the registered artifact kinds from `packages/graph-workflow` (the registry is in `types/artifact-registry.ts`; `KIND_SCHEMAS` and `resolveKindFamilyRoot` are the relevant exports). **Report the actual count and which family roots have a renderer** — the register says "about a third", but verify rather than repeating it.

- [ ] **Step 2: Write failing tests**

```ts
it("previews a node's second output, not only the first", () => {});
it("lets the author switch between a node's outputs", () => {});
it("renders a readable fallback for a kind with no dedicated renderer", () => {});
it("says why when a value cannot be previewed, instead of a blank card", () => {});
```

- [ ] **Step 3: Run, watch fail.**

- [ ] **Step 4: Implement**

- **Multi-output:** thread all output ctx keys through the projection, not just `[0]`. Give the widget a way to pick — a small selector when a node has more than one output; unchanged UI when it has one.
- **Fallback renderer:** a generic structured view (bounded JSON / key-value list) for kinds with no dedicated component, so an unknown kind is *legible* rather than blank. Prefer a real fallback over adding renderers for every kind.
- **Never render nothing silently.** If a value cannot be shown, say which kind it is and why.

git commit -m "fix(workflow-builder): preview every output, cover every kind, never blank silently (G-011)"

## Task 3 — G-022: show the values, not a pointer

**This is the batch's headline and its hardest part.**

`OcrResultSchema` (`packages/graph-workflow/src/types/kind-schemas.ts:18`) is documented as *"a blob POINTER to the full OCR payload, not the payload"*. **That is a deliberate architecture decision** — large payloads stay out of ctx. Do not change it.

The defect is that the *preview* shows the pointer. An author cannot answer "did this step work?" by looking, and the whole method for debugging a wrong result — walking each step's output — is unavailable.

**So the fix is to dereference, bounded, at preview time.**

**Files:**
- Modify: the preview-cache endpoints (`workflow.controller.ts:922` `GET :id/preview-cache`, `:1012` `…-batch`) and their service
- Modify: `OcrResultPreview` / `render-kind-value.tsx`
- Test: both sides

- [ ] **Step 1: Decide where dereferencing happens, and say why**

Server-side is strongly preferred: the browser has no blob credentials, payloads can be large, and the endpoint already exists and is already authorised. **If you conclude otherwise, stop and explain before building.**

- [ ] **Step 2: Bound it before you build it**

An OCR payload can be enormous. Decide and document explicit limits — how many fields, how much text, how many pages — and enforce them **server-side**, so a 300-page document cannot turn a preview into a multi-megabyte response. State the limits in the response so the UI can say "showing the first N of M".

**A truncated preview that says it is truncated is correct. A preview that silently shows part of the data is a new instance of the exact class of bug this whole effort exists to remove.**

- [ ] **Step 3: Write failing tests**

```ts
// backend
it("resolves a blob-backed OcrResult into a bounded excerpt", () => {});
it("reports the excerpt's limits so the client can say what was omitted", () => {});
it("degrades gracefully when the blob is gone", () => {});
it("does not dereference for kinds that are not blob-backed", () => {});

// frontend
it("shows extracted field values for an OcrResult, not a blob key", () => {});
it("says the preview is truncated when it is", () => {});
```

## Notes for the implementer

**Do the tasks in order.** G-012 gives the widget an honest state model; G-011 and G-022 both render into it.

**Bounding is a correctness requirement, not an optimisation.** An unbounded preview of a 300-page OCR payload will look like it works on your test document and fall over on a real one.

**Do not change the pointer-based ctx model.** Keeping payloads out of ctx is deliberate. The preview dereferences; the data model stays as it is.

**Do not fix anything outside G-012, G-011, G-022.** Replay, cache TTL, run path and validation navigation (G-004, G-024, G-014, G-010) are batch 8 and will touch some of the same files — leave them.
